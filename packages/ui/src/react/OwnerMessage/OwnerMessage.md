# OwnerMessageView

Import `OwnerMessageView`, `OwnerMessageViewProps`, `pendingQuestion`, and `approvalDecisions` from `@tensquads/ui/react`. Pass owner messages as `messages`. The view sorts valid messages by `seq`, keeps invalid messages out of the display, and reports invalid or unknown messages through `onUnknown`. Option questions emit an `OwnerAnswer` body through `onCommand`. The host adds `commandId` and `at` before posting it.

Replies, result summaries, and result evidence are plain text with linked URLs. Evidence follows the summary as a list. A free text question includes a note to use the host message box. Use `pendingQuestion(messages)` to find the newest valid unanswered free text question by `seq` and send the next composer value as an `OwnerAnswer`. Option questions lock after a selection and mark the chosen option. A matching `question_answered` message disables its options. It preserves a local selection but does not identify a chosen option after a reload.

Approval requests use [ApprovalCard](../ApprovalCard/ApprovalCard.md), with `actionLabels` passed through. Pass `squadmates` as a map from bot ids to `AgentSlug` values. ApprovalCard and status messages show a Squadmate only when the bot id is an own property of this map and its value is a valid `AgentSlug`. Inherited properties, including prototype keys such as `constructor`, are ignored. Missing or invalid mappings show no agent. Status messages show an attempt label only above attempt 1. An `action_not_confirmed` message uses ChatError with `what` as its body. The view sets language and direction from `locale`, which defaults to English.

## Platform contract

The [platform schemas](../../schemas/platform.ts), exported from `@tensquads/ui/schemas`, restate `moeghashim/tensquads-platform-amp` commit `b09e197ae4578995d3c3d1a5be9330e1a7da600e`. They export eight owner message types and the platform owner commands. `PLATFORM_OWNER_MESSAGE_TYPES` lists the eight message literals in platform order. `approval_request` requires the `amount`, `bot`, and `taskId` keys. `amount` is in millionths of a US dollar and may be null. `approval_decided` locks the matching approval card using the highest `seq` for an approval id. Message decisions take precedence over the `approvalDecisions` prop. The exported `approvalDecisions(messages)` helper applies the same rule for hosts. `question_answered` closes the matching question as described above. Both messages render no content.

The schemas entry exports `ownerMessageCommand({ messageId, channel, text })`, `ownerAnswerCommand({ questionId, text })`, `approvalDecisionCommand(request, "approve" | "reject")`, and `cancelTaskCommand({ taskId })`. These validate command bodies without generating ids or timestamps. `approvalDecisionCommand` retains the request's approval id and content hash. Use `withCommandMeta(body, { commandId, at })` to validate a full command before posting it to `POST /v1/commands`. Reuse the same command id for a retry. `formatMillionths(value, locale)` formats safe integer millionths as US dollars with two decimal places; for example, 20000000 formats as $20.00 in English.

OwnerMessageView has no OpenUI definition because it consumes platform messages. For inline streamed content, use the [ApprovalCard OpenUI adapter](../ApprovalCard/ApprovalCard.md). Platform controls return command bodies through `onCommand`; inline OpenUI controls emit chat actions.

Use `labels` to override `answerHint`, `attempt`, and `errorTitle`. Use `approvalLabels` to override the ApprovalCard copy. Defaults follow `locale`.
